     1→# ProjectOS — Worklog (Single Source of Truth)
     2→
     3→Product: **ProjectOS** — Jira-class multi-tenant project management portal built from the uploaded blueprint (orgs → projects → issues, workflow engine, sprints, kanban board, backlog, reports, notifications, audit log).
     4→
     5→## Architecture decisions (locked)
     6→
     7→- **Stack**: Next.js 16 App Router + TypeScript, Prisma + SQLite (`db/custom.db`), shadcn/ui (New York), dnd-kit, recharts, zustand, date-fns, lucide-react.
     8→- **Single visible route `/`** — the whole portal is one SPA in `src/app/page.tsx` → `<PortalApp />` with client-side view switching (zustand). NO other pages. Backend = Next.js route handlers under `src/app/api/**` (NOT server actions).
     9→- **Auth**: custom session tokens (httpOnly cookie `pos_session`, 30 days). Password hashing: node:crypto `scrypt` (`src/lib/auth.ts` — `hashPassword`, `verifyPassword`). Helper `getSessionUser(req)` returns `{user, org, role}` or null. Route handlers read cookies via `req.cookies.get('pos_session')`.
    10→- **DB client**: `import { db } from '@/lib/db'`.
    11→- **Workflow engine**: statuses are DB rows per org (category TODO | IN_PROGRESS | DONE). ALL status changes go through `transitionIssue()` in `src/lib/workflow.ts` (validates status exists in org, writes Activity, fires Notifications). No direct `statusId` writes elsewhere.
    12→- **Automation rules (v1)**: on issue.assigned → notify assignee; on issue.status_changed → notify reporter + assignee (excluding actor); on comment.created → notify assignee/reporter + @mentions parsed from body (`@Full Name`).
    13→- **Design language**: light UI on white background, zinc/stone neutrals, **amber-600 (#d97706) accent**. FORBIDDEN: blue-*, indigo-* Tailwind classes. Semantic: emerald=done/success, rose=bug/highest/critical, amber=in-progress, violet=epic, orange=high. Sidebar dark (stone-950/900), content light. Rounded-lg cards, consistent p-4/gap-4. Sticky footer n/a (app shell uses full-height flex). Every list area: `max-h-… overflow-y-auto` + thin custom scrollbar.
    14→- All dates serialized as ISO strings. All JSON responses `NextResponse.json`. All API errors: `{ error: string }` with proper status (400/401/403/404).

    31→## API CONTRACT (both agents MUST follow exactly)
    32→
    33→Shared DTO shapes:
    34→
    35→```ts
    36→// Minimal user DTO used everywhere as "assignee"/"author"/"lead"/"user"
    37→UserDTO      = { id, name, email, avatarColor, title: string|null }
    38→OrgDTO       = { id, name, slug }
    39→ProjectDTO   = { id, key, name, description, color, icon, lead: UserDTO|null, archived: boolean, issueCount: number }
    40→TypeDTO      = { id, name, color, icon, order }
    41→StatusDTO    = { id, name, category: 'TODO'|'IN_PROGRESS'|'DONE', color, order }
    42→PriorityDTO  = { id, name, color, order }
    43→LabelDTO     = { id, name, color }
    44→SprintDTO    = { id, projectId, name, goal, startDate: string|null, endDate: string|null, status, order }
    45→CommentDTO   = { id, body, createdAt, author: UserDTO }
    46→ActivityDTO  = { id, type, field, oldValue, newValue, createdAt, user: UserDTO, issueId: string|null }
    47→NotificationDTO = { id, type, title, body, issueId, read, createdAt }
    48→IssueDTO = {
    49→  id, key, number, summary, description,
    50→  typeId, type: TypeDTO,
    51→  statusId, status: StatusDTO,
    52→  priorityId, priority: PriorityDTO|null,
    53→  assigneeId, assignee: UserDTO|null,
    54→  reporterId, reporter: UserDTO|null,
    55→  labels: LabelDTO[],
    56→  storyPoints: number|null, dueDate: string|null,
    57→  estimateHours: number|null, remainingHours: number|null,
    58→  sprintId: string|null, parentId: string|null, order: number,
    59→  projectId, projectKey, projectName,
    60→  createdAt, updatedAt,
    61→  commentCount: number, subtaskCount: number, subtasksDone: number
    62→}
    63→```
    64→
    65→### Endpoints (all under /api, all return DTOs above)
    66→
    67→- `POST /api/auth/signup` body `{email,name,password,orgName,orgSlug}` → `{user:UserDTO, org:OrgDTO}` (creates org + ADMIN membership + default issueTypes/statuses/priorities/labels; slug unique-ified; auto-login)
    68→- `POST /api/auth/login` `{email,password}` → `{user, org}`
    69→- `POST /api/auth/logout` → `{}`
    70→- `GET  /api/auth/me` → 401 or `{user, org, role}` (role = membership role)
    71→- `GET  /api/workspace` → `{ user, org, role, members: (UserDTO&{role})[], projects: ProjectDTO[], issueTypes: TypeDTO[], statuses: StatusDTO[], priorities: PriorityDTO[], labels: LabelDTO[] }` — members exclude nothing (all org members)
    72→- `POST /api/projects` `{name,key,description?,color?,icon?,leadId?}` → ProjectDTO (activity project.created)
    73→- `PATCH /api/projects/[projectId]` `{name?,description?,color?,icon?,leadId?,archived?:boolean}` → ProjectDTO
    74→- `DELETE /api/projects/[projectId]` → `{}` (403 unless ADMIN)
    75→- `GET /api/projects/[projectId]` → `{ project: ProjectDTO, issues: IssueDTO[], sprints: SprintDTO[], activity: ActivityDTO[], stats: { total, todo, inProgress, done, points, donePoints, overdue } }`
    76→- `POST /api/issues` `{projectId, typeId, summary, description?, priorityId?, assigneeId?, sprintId?, storyPoints?, dueDate?, parentId?, labelIds?: string[]}` → IssueDTO (number auto-increment per project, key = `${projectKey}-${number}`, activity issue.created, notify assignee)
    77→- `GET /api/issues/[issueId]` → `{ issue: IssueDTO, comments: CommentDTO[], activity: ActivityDTO[], subtasks: IssueDTO[] }`
    78→- `PATCH /api/issues/[issueId]` — any of `{summary?, description?, typeId?, statusId?, priorityId?, assigneeId?, sprintId?: string|null, storyPoints?: number|null, dueDate?: string|null, estimateHours?, remainingHours?, labelIds?: string[], order?: number}` → IssueDTO. Status changes MUST route through workflow transition (activity issue.status_changed + notify). assignment change → activity issue.assigned + notify. Writes activity rows for each changed field (issue.updated).
    79→- `DELETE /api/issues/[issueId]` → `{}`
    80→- `POST /api/issues/[issueId]/comments` `{body}` → CommentDTO (activity comment.created, notify assignee/reporter/@mentions)
    81→- `DELETE /api/comments/[commentId]` → `{}`
    82→- `POST /api/sprints` `{projectId, name, goal?, startDate?, endDate?}` → SprintDTO
    83→- `PATCH /api/sprints/[sprintId]` `{name?, goal?, startDate?, endDate?, status?}` → SprintDTO. Transition rules: →ACTIVE only if no other ACTIVE sprint in project (move it after current active? no—409 error string); →COMPLETED moves its unfinished (status.category != DONE) issues back to backlog (sprintId=null) and keeps finished ones; activity sprint.started / sprint.completed + notify members.
    84→- `DELETE /api/sprints/[sprintId]` → `{}` (issues → backlog)
    85→- `GET /api/dashboard` → `{ stats: { myOpen, totalIssues, openIssues, completedThisWeek, activeSprints }, myIssues: IssueDTO[] (assignee=me, status!=DONE, max 8), upcomingDue: IssueDTO[] (assignee=me, dueDate set, not done, max 5), activity: ActivityDTO[] (max 12), createdVsResolved: [{date:'MM-DD', created, resolved}] (last 14 days), activeSprintCards: [{sprint: SprintDTO, projectName, projectKey, total, done, points, donePoints}] }`
    86→- `GET /api/notifications` → `{ notifications: NotificationDTO[], unread: number }`
    87→- `POST /api/notifications/read` `{ids?: string[]}` (empty ids = mark all) → `{}`
    88→- `GET /api/search?q=...` → `{ issues: IssueDTO[] (max 12), projects: ProjectDTO[] (max 5) }` (match key/summary/description, org-scoped)
    89→- `GET /api/reports/burndown?sprintId=` → `{ total, completed, points: [{date:'MM-DD', remaining, ideal}] }`
    90→- `GET /api/reports/velocity?projectId=` → `{ sprints: [{id, name, committed, completed}] }` (COMPLETED + ACTIVE sprints, order asc, max 8)
    91→- `GET /api/reports/overview?projectId=` → `{ statusDist: [{name, color, count}], priorityDist: [{name, color, count}], assigneeLoad: [{userId, name, avatarColor, open, done}], typeDist: [{name, color, count}] }`
    92→- `POST /api/members` `{email, name?, role?, title?}` → member UserDTO&{role} (invite: find-or-create user w/ random password; activity member.joined; 403 unless ADMIN/MANAGER)
    93→- `PATCH /api/members/[userId]` `{role}` → updated member (ADMIN only)
