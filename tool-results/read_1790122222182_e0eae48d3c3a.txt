     1→     1→Yes. I would build this as an **independent multi-tenant project management platform**, basically a Jira-class system without depending on Atlassian APIs or Atlassian infrastructure.
     2→     2→
     3→     3→My recommendation is: **do not start with microservices**. Build a well-structured modular monolith first, with separate workers for background jobs. This will be much easier to build, test, and maintain. NestJS is designed around modular application structure and supports authentication, authorization, queues, scheduling, WebSockets, etc.; Next.js provides the frontend/full-stack application layer. ([NestJS Documentation][1])

    51→    51→
    52→    52→| Layer           | Technology                      |

    54→    54→| Frontend        | Next.js + React + TypeScript    |
    55→    55→| UI              | Tailwind CSS + component system |
    56→    56→| Backend         | NestJS + TypeScript             |

    58→    58→| Cache           | Redis                           |
    59→    59→| Background jobs | Redis + BullMQ                  |
    60→    60→| Authentication  | Keycloak self-hosted            |
    61→    61→| Object storage  | S3-compatible storage           |
    62→    62→| Search          | PostgreSQL FTS initially        |
    63→    63→| Realtime        | WebSocket                       |
    64→    64→| Email           | SMTP provider                   |
    65→    65→| Reverse proxy   | Nginx / Traefik                 |
    66→    66→| Containers      | Docker                          |
    67→    67→| Deployment      | VPS/cloud                       |
    68→    68→| Monitoring      | Prometheus + Grafana            |
    69→    69→| Error tracking  | Sentry/self-hosted alternative  |
    70→    70→| CI/CD           | GitHub Actions                  |
    71→    71→
    72→    72→Next.js currently supports the App Router and React-based application architecture. ([Next.js][2])
    73→    73→
    74→    74→NestJS provides modular architecture and documented authentication/security patterns, which fit a large product like this. ([NestJS Documentation][3])
    75→    75→
    76→    76→For SSO, I would use **self-hosted Keycloak** rather than writing SAML from zero. Keycloak supports OpenID Connect and SAML, and can act as an identity broker. ([Keycloak][4])
    77→    77→
    78→    78→For file uploads, use private object storage and short-lived signed URLs rather than sending large files through your API server. S3 supports presigned upload/download URLs. ([AWS Documentation][5])

    82→    82→# 3. Multi-Tenant Architecture
    83→    83→
    84→    84→This is the most important architectural decision.
    85→    85→
    86→    86→Every organization gets its own tenant:
    87→    87→
    88→    88→```text
    89→    89→Organization A
    90→    90→    ↓
    91→    91→Projects
    92→    92→Issues
    93→    93→Users
    94→    94→Dashboards
    95→    95→
    96→    96→Organization B
    97→    97→    ↓
    98→    98→Projects
    99→    99→Issues
   100→   100→Users
   101→   101→Dashboards
   102→   102→```
   103→   103→
   104→   104→Every important database table should contain:
   105→   105→
   106→   106→```text
   107→   107→organization_id
   108→   108→```
   109→   109→
   110→   110→Example:
   111→   111→
   112→   112→```text
   113→   113→issues
   114→   114→---------
   115→   115→id
   116→   116→organization_id
   117→   117→project_id
   118→   118→issue_key
   119→   119→summary
   120→   120→description
   121→   121→status_id
   122→   122→priority_id
   123→   123→assignee_id
   124→   124→reporter_id
   125→   125→story_points
   126→   126→due_date
   127→   127→created_at
   128→   128→updated_at
   129→   129→```
   130→   130→
   131→   131→Use PostgreSQL Row-Level Security as an additional isolation layer. PostgreSQL supports policies that restrict which rows a database user can read, insert, update, or delete. ([PostgreSQL][6])
   132→   132→
   133→   133→So security should be:
   134→   134→
   135→   135→```text
   136→   136→User
   137→   137→ ↓
   138→   138→JWT / Session
   139→   139→ ↓
   140→   140→Organization membership
   141→   141→ ↓
   142→   142→Role permission
   143→   143→ ↓
   144→   144→Project permission
   145→   145→ ↓
   146→   146→Issue permission
   147→   147→ ↓
   148→   148→Database tenant isolation
   149→   149→```
   150→   150→
   151→   151→Never rely only on frontend checks.

   924→   924→
   925→   925→Use an event-driven architecture.

   944→   944→Issue moves to "Code Review"

   946→   946→IF
   947→   947→Issue type = Story
   948→   948→
   949→   949→THEN
   950→   950→Assign to Team Lead
   951→   951→AND
   952→   952→Add label "review"
   953→   953→AND
   954→   954→Send notification
   955→   955→```
   956→   956→
   957→   957→Database:
   958→   958→
   959→   959→```text

   963→   963→automation_actions

   968→   968→
